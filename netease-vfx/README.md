# 咒术映界 · 网易基岩版验证工程 0.2.1

独立的网易 ModSDK 工程，包含 Python 2 兼容脚本、行为包、资源包与 GLSL ES 着色器。已接入下表中的术式及五条猫；不包含机械动力航空学物理、自动运镜和 Java 版完整猫咪演出战斗系统。

**当前为开发验证版。0.2.1 的游戏内画面、手臂与蓄力操作验证正在进行，尚未完成。** 已通过的离线检查为 54 项逻辑检查，以及 GLSL ES 100／300 编译、链接、栅格绘制和前景遮挡检查。这些结果不代表手机、其他显卡或 RenderDragon 已通过实机验证，也不代表已经完整还原 Java 版特效。

## 0.2.1 本次改动

- 重做茈的体积银河着色器：中心由高亮星云、星带与不规则亮结组成，外层保留紫色星云和 `#2f22bd` 深蓝紫边缘；使用体积采样表现内部层次。
- 银河与空气场加入顺时针旋转、向中心卷入的弯曲流线及场景折射；保留紫外白内、间歇换位的闪电。实际游戏的亮度、旋转方向和遮挡仍在核对。
- 茈的输入改为每次按下分配独立 token 与序号，服务端将开始、松开、取消绑定到同一次施法；重复开始、重复松开和旧输入不再用于重新触发当前技能。合成状态一旦提交，晚到的松开不会把大茈回退成小茈。
- 保留原生蓄力物品的开始流程，用对应的停止／释放事件结束输入，切换物品时取消未提交输入；兼顾鼠标与触控的事件差异。
- 修正事件监听对象必须拥有对应回调方法的注册方式，并保留脚本 tick 无参数调用的兼容处理。原来错误的监听绑定或必填事件参数会中断更新，导致技能停住、动作或释放异常。

## 获取与操作

在创造物品栏取得术式物品，或由管理员输入 `!rift kit` 一次取得全部 11 种术式物品与术式增幅道具。电脑版使用物品键通常为鼠标右键；下文“按住／松开”指原生物品使用操作。触屏沿用该客户端的物品使用操作，具体操作手感仍待实机确认。

所有时间按服务端 30 Hz 脚本 tick 推进；服务器卡顿时实际经过的墙钟时间可能更长。

| 术式 | 操作与当前参数 |
| --- | --- |
| 苍 | 按住后球体缓慢前进，缓慢牵引至视角方向，距施法者的目标距离最多约 12 格；松开后短暂惯性滑行并停留。总存续约 10 秒，球体半径 1.8 格，牵引检查范围 7 格。允许破坏时清除沿路可破坏方块，无法破坏的方块不阻挡其前进。 |
| 赫 | 按住不到 1.3 秒松开，发射小球；满 1.3 秒后松开进入冲击炮，持续按住至 2.6 秒会自动进入冲击炮。短球和炮的距离均为 32 格，炮持续约 0.9 秒；短球为小型红球。 |
| 小茈 | 按住不到 1 秒松开，进入自动蓄力 1 秒后发射；半径 1 格、距离 50 格。 |
| 合成茈 | 按住满 1 秒自动进入苍赫合成，不再接受回退小茈；合成 3 秒，再蓄力 1 秒发射。半径 3 格、距离 150 格。 |
| 200% 茈 | 先使用术式增幅道具，60 秒内以长按方式释放茈；仍走合成与蓄力流程，合成阶段即使用增幅状态，半径 5 格、距离 150 格。增幅目前为独立脚本状态，不是原版药水系统。 |
| 无限制茈 | 发射赫，使赫的小球或冲击炮命中尚存的苍；两者被消耗，在苍的位置融合，约 1.6 秒后爆发。伤害检查半径 24 格，破坏方块有独立开关，默认关闭。 |
| 灶·开 | 使用后约 1.6 秒自动发射火焰箭；最远 96 格，碰撞后爆发，爆发检查半径 12 格。尚未发射时切换物品会取消。 |
| 解 | 短按单次斩击；蓄力约 0.7 秒后松开，或持续至 1.2 秒，释放快速多斩。索敌最远 28 格，在出手前摇结束时确定方向。 |
| 捌 | 同样支持短按与蓄力快速多斩，索敌最远 18 格；按随机斩面处理普通方块和生物，不创建或拆分动态结构。 |
| 伏魔御厨子 | 使用物品展开；默认半径 40 格、持续 5 秒。包含神龛、深红天空、青色镜水面与随机斩击；单目标与多目标使用不同斩击安排。 |
| 无量空处 | 使用物品展开；默认半径 40 格、持续 5 秒。白色侵染后呈现宇宙、银河、黑洞和红紫粉高速光束；冻结范围内对象，无直接伤害。 |
| 咒力缠拳／黑闪 | 手持咒力缠拳攻击生物；每累计两次成功普通命中，下一次为黑闪，具有更高伤害与击退。使用键也有短按出拳与蓄力上升拳；尚未移植 Java 版完整体术连招。 |
| 无下限术式 | 使用开启，持续最多 6 秒；再次使用关闭。当前脚本在有效期间拦截符合条件的伤害，宿傩领域等指定来源除外。 |
| 反转术式 | 使用开启，持续最多 5 秒，每秒恢复 10 点生命；受到伤害会打断，再次使用也可关闭。 |

无量空处的玩家目标会被限制移动、跳跃、转动视角和攻击。信息碎片每个领域对同一玩家只填充一次空背包格，堆叠上限 1；背包仍有碎片时持续刷新缓慢 I、虚弱 I、挖掘疲劳 I，丢出的碎片会被删除。普通生物与投射物的冻结状态在领域结束后恢复，施法者免疫自己的领域。

领域发生重叠对抗时，已建立对抗的双方施法者免疫对方领域，5 秒后随机移除一方领域。冻结期间是否能够顺利触发反开领域、原生受伤冷却对连续斩击的影响仍需要实机验证。

## 五条猫、模型与手臂

五条猫保留原模型与双贴图转换、独立自发光眼睛，生命值 800；中立，受攻击后还击，免疫普通摔落，包含行走、尾巴和蓄力姿态。基础技能 AI 可使用小／大茈，生命值低于一半后可释放无量空处；首次展开无量空处会摘眼罩并保持。这里没有移植 Java 版完整招式决策、宿傩猫、魔虚罗和剧情阶段管理。

术式手持采用独立玩家手臂几何与姿势层，并在切回普通物品后恢复物品显示。**全局“隐藏手”设置与“拿起术式后手消失”是两个需要分别检查的问题；后者仍在本轮实机排查中，不能仅靠关闭隐藏手设置认定已修复。** 经典与纤细皮肤、第一／第三人称以及其他玩家观察均需继续核对。

无量空处目前替换天空并调暗地形，没有实现 Java 版“隐藏领域内全部方块”。水面使用屏幕空间反射与程序纹理，不等于重新渲染完整镜像世界；屏幕外的反射对象可能无法显示。全套配置 GUI 也尚未接入。

## 管理员调试命令

命令开头是 `!`，不是 `/`。需要管理员权限。

```text
!rift kit                    获取全部术式物品和术式增幅道具
!rift cat                    在面前召唤五条猫
!rift purple                 启动小茈的调试流程
!rift purple big             启动合成茈的调试流程
!rift purple 200             启动增幅合成茈的调试流程
!rift blue                   启动苍
!rift red                    启动赫
!rift fuga                   启动灶·开
!rift dismantle              启动解
!rift cleave                 启动捌
!rift infinity               切换无下限
!rift reverse_technique      切换反转术式
!rift void                   展开无量空处
!rift shrine                 展开伏魔御厨子
!rift domain 40 5            后续领域半径 40 格、持续 5 秒
!rift blocks on              开启术式方块破坏
!rift blocks off             关闭术式方块破坏，默认关闭
!rift unlimited_blocks on    允许无限制茈破坏方块，仍需要总破坏开关开启
!rift unlimited_blocks off   禁止无限制茈破坏方块，默认关闭
!rift flash on               开启闪白
!rift flash off              关闭受该配置控制的闪白
!rift clear                  清理当前技能、领域及待处理破坏，恢复被冻结对象
```

聊天命令用于调试，不代替手持物品的按下／松开操作。领域半径可设 4—50 格，持续时间可设 2—60 秒。领域参数和闪白设置为当前运行期设置；方块破坏总开关与无限制茈破坏开关保存到世界。

方块破坏独立于 `mobGriefing`，通过替换为空气处理，不产生掉落物。保护方块跳过；每脚本 tick 的实际破坏预算为 48 格，避免一次性处理大区域。客户端最多绘制最近 4 个茈、6 个其他术式和 16 个斩击／命中特效，该绘制预算不等于服务端技能存活数量限制。参数见 `pack/behavior_pack/jujutsuScripts/config.py`。

## MC Studio 导入与版本确认

1. 使用 MC Studio 的“作品库 → 基岩版组件 → 附加包 → 本地导入”，选择构建生成的 `dist/JujutsuNetease-0.2.1.zip`。
2. 如入口要求目录，解压后选择同时包含 `behavior_pack`、`resource_pack`、`work.mcscfg` 的目录，并确认行为包、资源包同时启用。
3. 已存在的同 UUID 测试工程可以使用下面的安装脚本更新，保留原 Studio 元数据与测试设置。**Studio 工程名称／目录可能仍显示 `JujutsuNetease-0.1.0`；这是保留的工程名，不代表内部仍运行 0.1.0。** 应核对包清单与当前启动日志中的 0.2.1。
4. 在创造测试世界使用 `!rift kit` 取得技能，分别检查短按、持续按住、切换物品、连续释放和不同人称。修改包后应重新启动测试客户端，避免旧脚本与旧资源混用。

本轮验证针对 Studio 3.8 OpenGL 测试客户端；目前不把 RenderDragon 视为已经支持的高保真路径。ZIP 是网易附加包工程，不是 Java JAR 或国际基岩版 JavaScript Script API 包，也没有执行对外发布。

Python 运行异常优先查看 `%LOCALAPPDATA%/Netease/MCSafaiaServer/log_storages/` 下当前测试日志。游戏目录中的 `Debug_Log*.txt` 主要记录引擎信息，两者不要混淆。服务端日志应出现 `server 0.2.1 loaded; tokened purple input; 30 Hz`。

## 开发与验证

在本目录运行项目提供的脚本：

```powershell
python tools/build.py
python tools/verify.py
python tools/verify_all.py
python tools/verify_charge021.py
python tools/check_shaders.py
# 更新现有同 UUID Studio 工程；自动备份，保留 Studio 元数据
python tools/install_studio.py "现有 Studio 工程目录"
```

- `build.py` / `extend_pack.py`：转换原模型、动画、图标与声音，生成稳定 UUID 清单并打包。
- `verify.py` / `verify_all.py` / `verify_charge021.py`：检查数据与 Python 2 语法兼容性，并用离线替身验证技能时间线、蓄力输入去重、事件回调、冻结恢复、多技能共存、伤害安排及渲染参数等。
- `check_shaders.py`：结合本机 Studio 着色器头文件检查 GLSL ES 100／300；使用本机 OpenGL 驱动进行编译、链接、栅格绘制、关闭效果时画面保全及茈的前景遮挡检查。
- `build/reference`：官方文档和 SDK 接口快照，不装入组件包。

**已确认离线结果：54 项逻辑检查通过；GLSL ES 100／300 编译与栅格、遮挡检查通过。** 离线检查使用合成背景／深度缓冲与本机驱动，不能据此承诺所有技能的游戏内观感、第一人称手臂、移动端帧率或其他 GPU 都正常。本轮实机验证正在进行；手机与 RenderDragon 的画质、性能和兼容性没有完成验证。

构建需要 Python 3、Pillow 与旁边的 `neoforge-vfx` 原素材。游戏内脚本使用 Python 2 标准库及 ModSDK。离线图形检查依赖本机 Java／LWJGL 环境。上述构建和安装命令属于本项目工具，不是网易官方完整工作流 CLI。
